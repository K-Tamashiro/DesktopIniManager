# MFT Differencer

DIM下部の **MFT Diff** から開きます。Source／Targetは左右のルートであり、同期方向ではありません。

1. 2つのルートを指定します。MFT列挙にはローカルNTFSと管理者権限が必要です。MFTを取得できない場合は通常のファイルシステム走査に切り替えます。
2. **Compare** を押します。既存のFastVolumeIndexでファイルを列挙し、各ファイルの更新日時（UTC）とサイズを取得して相対パスで比較します。同じボリュームは1回だけMFTを列挙します。隠しファイルも対象です。
3. 比較中は画面下部に進捗を表示します。MFT取得中は不定進捗、メタデータ取得中はSource／Target合計の処理件数を1つのProgressで表示します。完了・失敗時に進捗バーを閉じます。
4. 左ツリー上部の「同一・差異・左だけ・右だけ」を組み合わせて表示を切り替えます。初期値は「差異・左だけ・右だけ」です。選んだ種類のファイルがあるフォルダーと関連する親フォルダーを表示します。フォルダー件数は子孫を含み、チェックは絞り込み後も維持されます。初期状態は未選択です。保存する基本ツリーは保持し、表示の絞り込みだけを行います。
5. ダブルクリックでReadonlyのDIFF VIEWを開きます。テキストは行番号、追加・削除・変更の色分け、共通スクロール、中央マップと前後移動に対応します。画像は共通倍率、共通スクロール、左上揃えで表示します。登録済み外部エディターへ左右それぞれを送れます。
6. **Source → Target 同期…** または逆方向を選択します。対象総数とコピー／上書き／削除の内訳を確認して実行します。送り元にない選択ファイルは送り先から削除されます。
7. 個別の成功・失敗をログと結果画面で確認します。処理後はMFTから再比較します。再比較が失敗した場合は同期を無効にし、比較失敗を表示します。

## 保護と比較範囲

- `.git`というパス要素は大文字・小文字を問わず除外します。`.git`ファイル（worktree/submodule）も対象外です。`.gitignore`は通常ファイルとして扱います。
- 比較、プレビュー、外部エディター送出、同期の各入口でパスを検証します。ボリューム全体のMFT列挙にはGitのレコードも含まれますが、Git配下のファイルを開いたり差分結果へ追加したりしません。
- 絶対パス、親への遡り、代替データストリーム、ルート外パス、重複・包含関係のルートを拒否します。リンク／ジャンクションを含む比較は中断し、不完全な比較結果による削除を防ぎます。同期ではハードリンクも拒否します。
- 同期直前に双方の存在・サイズを再検証し、Compare datesがONの場合は更新日時も検証します。コピーは送り先と同じディレクトリの一時ファイルに完了させ、再検証後に置き換えます。失敗しても他の選択ファイルを処理します。
- ファイルの内容・ハッシュでの同一判定はしません。更新日時とサイズが同じファイルは、内容が違っていても「同一」に分類します。「同一」をONにすると一覧に表示します。テキストを読むのはDIFF VIEWを開いたときだけです。
- 更新日時が同じでサイズだけが異なる場合は「サイズ差異」と表示し、NEW／OLDを付けません。
- フォルダー同士の同期・空フォルダーの削除は行いません。ファイル／フォルダーの衝突は個別失敗として扱います。Git履歴操作やマージは実装しません。
- 比較・同期はファイルシステム全体の排他スナップショットではありません。外部アプリケーションによる書き換えを止めて実行してください。同じサイズ・日時を保つ書き換えは検出できません。

## 保存と表示

`%LOCALAPPDATA%\DesktopIniManager\mft-differencer.xml` に比較の左右ルートを保存します。次回起動時にルートを復元し、Compareで比較を再実行します。メイン画面のPhysical／Solutionツリーは別の `folder-trees.xml` に階層・展開状態・選択位置・アイコンを保存し、起動時に復元します。検索結果や絞り込みによって基本ツリーを上書きしません。

同期ログは同じディレクトリの `mft-sync-yyyyMMdd-HHmmss-fff.log` に保存します。

画像はWPF対応のPNG、JPEG、BMP、GIF、ICO、TIFF、WDP／JXRを対象とし、GIF／ICOは先頭フレームを表示します。テキストはBOM、UTF-8、Shift-JISを読み、8 MB超／10万行超／バイナリは外部エディターへ案内します。大きなテキストはメモリ使用量を制限した簡易行対応を使用します。

## 開発時の検証

v1.7.0ではOBJ／BINフィルターを追加しました。どちらも初期値はOFFで、任意の階層にある同名フォルダー配下をツリー・一覧から隠します。既存のチェックは保持され、非表示の選択件数に含まれます。

**Clean solution** は選択したソリューションのMSBuild Cleanを実行し、完了後に再比較します。実行中のDIMを含むソリューションはクリーンできません。DIM自身をクリーンする場合は、比較対象外のフォルダーに展開した配布版から起動してください。

対応対象はローカルNTFSです。Google Driveなどのクラウド仮想ドライブ、ネットワーク、NASは非対応です。仮想ドライブでは更新日時の精度差により同期検証が失敗する場合があります。

Diff Viewはexe・dll・cacheなどの既知のバイナリを開く前に英語メッセージで除外します。画像は左右共通倍率で自動フィットし、Fit／100%で倍率を切り替えられます。

Visual StudioのMSBuildで `Tests\DesktopIniManager.DifferencerTests.csproj` をビルドし、`Tests\bin\Debug\DesktopIniManager.DifferencerTests.exe` を実行します。テストは実行ファイルの隣に独立したfixtureを作成し、実リポジトリを同期しません。

`--mft` を付けると実MFTの列挙も検証します。このオプションにはWindows管理者権限が必要です。通常テストでは双方向の同期、保護パス、変更検出、テキスト行対応、チェック連動、WPFの生成、保存と復元を検証します。

## スクロールの負荷対策と検証

比較一覧は行高を80に固定し、画面外の先行生成を無効にしています。画像の読み込みは行が120ms以上表示された場合に開始し、画面外に出た画像は解放します。サムネイルは縦横とも最大96×64の範囲に収め、ファイル種類のアイコンを共有します。通常画面のアイコン取得処理は変更していません。

テスト実行ファイルに `--scroll` とDIMの `App.xaml` の絶対パスを渡すと、3万件の差分・3千フォルダーの画面を画面外に開き、ファイル一覧とツリーのスクロールを実際のWPF Dispatcherで実行します。生成行数・応答間隔・停止後のCPU時間・画像保持数を記録し、画面外の行や画像が過剰に残れば失敗します。実MFTや実リポジトリへの同期は行いません。
## 種類の組み合わせフィルター

ツリー上部の丸い選択表示は、複数を同時にON/OFFできる切り替えです。「差異」は両側に存在して更新日時またはサイズが異なるファイル、「左だけ」はSourceのみ、「右だけ」はTargetのみです。全OFFでは一覧が空になります。切り替えでMFTの再取得やファイル内容の読み込みは行いません。

同一ファイルは閲覧専用で同期チェックを無効にします。フォルダーのチェックは、現在表示している種類の差分ファイルに適用します。非表示になったファイルの既存のチェックは保持し、選択件数に「非表示N件を含む」と表示します。同期の確認件数にはその選択も含まれます。
