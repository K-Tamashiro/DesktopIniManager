# DesktopIniManager v3.1.0 — DIR edition

Prepared: 2026-09-20

This release improves everyday file search, solution browsing, context-menu
exports, and solution build actions over v3.0.0.

## Changes

- Include files directly under the search root in file searches.
- Add previous/next match navigation below the search box, with wraparound and
  a current/total indicator. Align file highlighting with search matching and
  clear navigation targets when replacing the displayed list.
- Show the selected Solution folder's immediate files without substituting a
  same-named child directory. Respect `EnableDefaultItems=false` and expand
  explicit wildcard includes when reconstructing project folders. Unregistered
  nested solutions and release folders no longer enter these explicit-item trees.
- Add icon-based **Tree > Text Editor**, **Tree /F > Text Editor**, and
  **File List > Text Editor** actions. Tree exports use DIM's retained folders
  and known files; they do not invoke tree.exe or enumerate the disk again.
  File List exports the displayed filenames in order, one per line, without
  headings, paths, bullets, or indentation.
- Add solution-configuration **Build** and **Rebuild** menus. These actions are
  enabled only in the Solution view; Physical and Search menus show them disabled.
- Add script execution from the file context menu and the command field.
- Prepare file context menus before their first opening and apply the shared
  theme to build submenu items.
- Support English/Japanese main-window context menus, with English fallback
  for Chinese/Korean, and standardize Tree /F and Text Editor labels.
- Improve file-list counts, direct-child highlighting, and Diff View line and
  difference-overlay alignment.

## Upgrade and requirements

Package: `DesktopIniManager-v3.1.0-DIR-win-x64.zip`

Extract into a fresh directory and run `DesktopIniManager.exe`. Keep all files
and subdirectories together. Windows 10/11 x64 and .NET 10 Desktop Runtime x64
are required; the runtime is not bundled. Build/Rebuild/Clean require MSBuild.
Text exports use the configured external editor.

Use the Git acquisition button to rebuild saved Solution trees after upgrading.
Project parsing does not fully evaluate MSBuild imports, conditional items, or
Visual Studio's virtual nodes. Tree /F exports only file information DIM already
holds. File List exports the current list, including its existing display limit.

Folder comparison still uses size and optional timestamps, not content hashes.
Synchronization can delete checked destination-only files after confirmation.

## Package and validation

`scripts/Build-Release.ps1` creates the framework-dependent ZIP and its SHA-256
sidecar, checking assembly versions, runtime requirements, and archive contents.
Artifacts are written under `release/` and are not committed to Git.

Automated tests and interactive acceptance checks are left to the maintainer.
No v3.0.0 test results are claimed as validation of v3.1.0.
GitHub publication and release tagging are separate from this local release.
