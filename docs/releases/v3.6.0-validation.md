# v3.6.0 公開前チェック

## 動作確認

- [ ] メイン：子フォルダーを右クリックして検索場所へ設定すると即座に走査し、そのルートの結果になる。
- [ ] メイン：走査中に別ルートを選んでも、キャンセル後に最後に選んだルートを走査する。続けて検索しても旧ルートのチェックを使わない。
- [ ] メイン：存在しないフォルダー・仮想ノードでは不正な検索場所を設定しない。ドライブ直下のドロップでも`C:\`が`C:`にならない。
- [ ] 比較：履歴、フォルダー選択ダイアログ、ドロップで同じパスを選んでも走査せず結果を保持。別パスなら走査する。
- [ ] 比較：Source / Targetのタイトルアイコンでそれぞれ再走査。走査中クリックでは古い走査をキャンセルして再走査する。
- [ ] Ctrl + 1 / 2 / 3で各画面へ移動。入力欄でも機能し、通常のShift + 数字による記号入力と、その後の文字入力が欠落しない。
- [ ] 比較・GREP：ダブルクリック、×、全削除、他削除が確認なしに動作。非アクティブタブの削除、最後のタブ削除、再起動後の履歴保存も確認。
- [ ] 同期：通常処理を最後まで続行後に失敗分を1回再試行。成功回復、恒久失敗、ファイルロック継続、正逆方向、子ファイルと親フォルダーの削除を確認。
- [ ] 同期：比較後に変更されたファイル・保護パスは再試行でも拒否。成功／失敗件数は操作数と一致し、Queue失敗を再登録しない。
- [ ] メイン：リスト・大／小アイコン・検索結果でダブルクリックしたファイルが関連付けアプリで一度だけ開く。空白やヘッダーでは開かず、複数選択からのドラッグも維持。

## 配布作成・公開

1. 上記を確認し、Release Notesの検証欄に実際の結果を反映する。
2. 修正版ソースから作者がReleaseビルドを作成する。
3. ビルド済みディレクトリを指定し、再ビルドせずパッケージを作成する。

```powershell
pwsh -File scripts/Build-Release.ps1 -PrebuiltDirectory bin/Release/net10.0-windows/win-x64
```

4. `release/DesktopIniManager-v3.6.0-win-x64.zip`と`.zip.sha256`を確認する。スクリプトはバイナリバージョン、同梱ファイル、ZIP内のファイル名、SHA-256を検査／生成する。
5. 最終ソースをコミット・pushし、そのコミットに`v3.6.0`タグを付けてpushする。
6. GitHub上の同名タグ／Releaseの有無を確認する。未作成なら次を実行する。

```powershell
gh release create v3.6.0 release/DesktopIniManager-v3.6.0-win-x64.zip release/DesktopIniManager-v3.6.0-win-x64.zip.sha256 --verify-tag --title "DesktopIniManager v3.6.0" --notes-file docs/releases/v3.6.0.md --latest
```

同名プレリリースが既にある場合は、タグが修正版コミットを指していることを確認し、修正版ZIPとSHA-256へアセットを更新してから`gh release edit v3.6.0 --prerelease=false --latest --notes-file docs/releases/v3.6.0.md`で正式版へ変更する。
